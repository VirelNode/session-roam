**Detection logic:** Scan `~/.claude/projects/-home-joe-Desktop/` for subdirectories that indicate agent-originated sessions rather than personal ones. The signals to check:

1. **Worktree directories:** Any directory matching `-home-joe-Desktop-*-worktrees-agent-*` indicates a Claude Code subagent spawned from a Desktop-namespace session. These are fine (they are Joe's own subagents). Skip these -- do NOT flag them.

2. **Federation project directories:** Check if any directory matches patterns like `-home-joe-Desktop-*claude-memory-system*` where the federation server might have been run from Desktop. This would indicate a federation agent leaked into personal namespace. However, this is unlikely since federation runs from `~/Projects/`. More practically:

3. **The real check:** Look for session `.jsonl` files in `-home-joe-Desktop/` that were NOT created by an interactive Claude Code session. The most reliable heuristic: check if any `-home-joe-Desktop/` subdirectories contain a `.claude/` internal directory suggesting they were a CWD for an automated agent (federation panes would create these).

**Simplified practical approach (implement this):**

Since the real risk is federation Zellij panes running from `~/Desktop`, check for known federation agent markers. Scan `-home-joe-Desktop/` for directories whose names suggest non-personal-project origins. The check:

```bash
session_dir="$HOME/.claude/projects"
personal_ns="$session_dir/-home-joe-Desktop"

if [[ -d "$personal_ns" ]]; then
    # Count total project dirs in personal namespace (exclude worktree dirs)
    total_personal=$(find "$personal_ns" -maxdepth 0 -type d 2>/dev/null | wc -l)
    
    # Check for any .jsonl files with federation/agent environment markers
    # Look for sessions created by processes with FEDERATION_AGENT_ID set
    agent_sessions=0
    while IFS= read -r jsonl_file; do
        # Check first line for federation markers
        if head -1 "$jsonl_file" 2>/dev/null | grep -q "FEDERATION_AGENT_ID\|federation-workspace\|notes-federation"; then
            agent_sessions=$((agent_sessions + 1))
            warn "Possible agent session in personal namespace: $(basename "$(dirname "$jsonl_file")")"
        fi
    done < <(find "$personal_ns" -maxdepth 2 -name "*.jsonl" -newer "$personal_ns" -mmin -10080 2>/dev/null)
    
    if [[ $agent_sessions -eq 0 ]]; then
        ok "No agent sessions detected in personal namespace"
    fi
    
    # Also warn if the personal namespace has an unusually high number of
    # recent sessions (>50 in the last week) which could indicate automated usage
    recent_count=$(find "$personal_ns" -maxdepth 2 -name "*.jsonl" -mmin -10080 2>/dev/null | wc -l)
    if [[ $recent_count -gt 50 ]]; then
        warn "High session volume in personal namespace (${recent_count} in last 7d) -- check for agent contamination"
    else
        info "${recent_count} session(s) in personal namespace (last 7d)"
    fi
else
    info "No personal namespace directory found (normal on fresh installs)"
fi
```

Make sure the new section prints an empty `echo ""` at the end to match the spacing pattern used by all other sections.

Create `FEDERATION-CWD-PIN.md` in the repo root documenting the specific change needed in the federation codebase to close the Zellij pane CWD gap. Per D-04, D-05.

Structure:

**Title:** "Federation Zellij Pane CWD Pinning"

**Problem:** Federation Zellij panes inherit the CWD of whatever terminal the Zellij session was created from. If the federation session is started from `~/Desktop`, all 4 pane agents (Claude, Gemini, Codex, Qwen) will create Claude Code sessions in `-home-joe-Desktop/`, colliding with personal sessions.

**Current State:** The federation's `session_registry.py` (at `~/Projects/claude-memory-system/extensions/notes-federation/session_registry.py`) defines pane layout and navigation but does NOT specify a CWD for pane sessions. The `send_to_zellij_pane()` function in `zellij_helpers.py` sends text to panes using `write-chars` but has no CWD control -- it writes into whatever shell is running in the pane.

**Recommended Fix:** Two complementary changes:

1. **Add `cwd` field to `SESSION_CONFIGS` in `session_registry.py`:**
```python
SESSION_CONFIGS = {
    "federation": {
        "cwd": "/home/joe/Projects/claude-memory-system",
        "agents": ["claude", "gemini", "codex", "qwen"],
        # ... rest unchanged
    },
    "qwen-federation": {
        "cwd": "/home/joe/Projects/claude-memory-system",
        "agents": ["qwen", "qwen-2", "qwen-3", "qwen-4", "qwen-5"],
        # ... rest unchanged
    },
}
```

2. **Inject `cd` command when initializing panes:** When the federation session bootstrap creates Zellij panes (or when the first command is sent to a pane), prepend a `cd /home/joe/Projects/claude-memory-system` before the agent command. This could go in the session initialization code or as a preamble in `send_to_zellij_pane()` on first use.

Alternatively, the Zellij layout file (if one is used) can specify `cwd` per-pane:
```kdl
pane cwd="/home/joe/Projects/claude-memory-system" {
    // ...
}
```

**Why `~/Projects/claude-memory-system`:** This is where the federation code lives. Sessions will land in `-home-joe-Projects-claude-memory-system/`, which is already the subprocess-mode namespace -- maintaining consistency.

**Scope Note:** This fix lives in the `claude-memory-system` repo, NOT in `session-roam`. This document serves as the specification for that change. The `session-roam` side (verify.sh section 9) will detect if the fix is not applied.

**Testing After Fix:** Run `./verify.sh` from the session-roam repo. Section 9 should show "No agent sessions detected in personal namespace". Also verify manually: start a federation Zellij session and confirm pane agents create sessions in `-home-joe-Projects-claude-memory-system/`, not `-home-joe-Desktop/`.
